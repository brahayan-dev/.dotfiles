# AGENTS.md

This file provides guidance to opencode and other AI coding agents working in this repository.

## Architecture

Multi-environment dotfiles repository. A small `justfile` dispatches to environment-specific Ansible playbooks that deploy configs via symlinks from `~/.dotfiles/files/` into `$HOME` and `~/.config/`.

### Environments

Two environments, partitioned at runtime by `os()` in the justfile (`macos` → `life`, `linux` → `linux`):

- **life** (macOS, default) — Personal dev: SSH, git, Python runtime (mise via `install`), Elm and JS toolchains (npm globals), API tokens (`GITHUB_TOKEN`, `ANTHROPIC_API_KEY`)
- **linux** (pacman-based Linux) — Same tooling as life (Python, Elm and JS) with Linux-specific packages

### Entry Point

```
./workstation <command> [entity]
```

The `workstation` shell script detects the OS to bootstrap deps (`just` + `ansible` via brew/pacman), then `exec`s `just --justfile justfile --working-directory "$script_dir"`. All dispatch lives in the justfile from that point on; the versioned toolchain comes from mise — Python via `./workstation install`.

### Commands

The command registry is the `justfile` at the repo root — `just --list` documents every recipe, and `@just` shorthand aliases live there too (`p`, `s`). Side-effectful recipes stop at the first failing line with a non-zero exit code.

| Command            | life | linux |
| ------------------ | :--: | :---: |
| `ping`             |  ●   |   ●   |
| `setup`            |  ●   |   ●   |
| `install`          |  ●   |   ●   |
| `connect github`   |  ●   |   ●   |
| `generate-aliases` |  ●   |   ●   |

- `setup` runs the Ansible playbook for the host's environment (`ANSIBLE_CONFIG` set by the `cfg` variable in the justfile).
- `ping` runs `ansible -m ping` against localhost as a sanity check.
- `install` installs the Python runtime via mise (`mise use -g python@latest`). The pyright LSP and ruff formatter ship as global deps (npm), not under the mise Python.
- `connect-github` authenticates with GitHub (SSH key + token + origin).
- `generate-aliases` emits shell `cd`/`nvim` aliases for known repositories in `~/.dotfiles`, `~/Projects` (the `repos` variable feeds the printf loop).

```

  linux/

    playbook.yml               Linux setup playbook
    AGENTS.md                  Linux env docs (symlinked to ~/.config/opencode/AGENTS.md)

```

### Ansible

Playbooks run against `localhost` via `hosts.ini`. The justfile sets `ANSIBLE_CONFIG=systems/life/ansible.cfg` (macOS) or `ANSIBLE_CONFIG=systems/linux/ansible.cfg` (Linux) with the `cfg` recipe variable, picks the playbook with the `playbook` variable, and passes `systems/.vault_` and `systems/.become_` as password files. The `common` role creates directories (`~/.ssh`, `~/.config`, `~/.config/ghostty`, `~/.config/opencode`), installs everything shared via the `package` module (`fennel`, `fnlfmt`, global npm packages, and cross-env packages like `mise`, `direnv`, `sqlite`, `opentofu`, `visidata` — `become` only on Archlinux), and symlinks nvim, `.zprofile`, `.zshrc`, and `files/opencode/opencode.json` → `~/.config/opencode/opencode.json`. Environment-specific roles only add packages and symlinks that differ per environment (SSH config, profiles, per-env AGENTS.md, Ghostty variants). The `macos` role (Darwin) installs the shared Homebrew base.

`roles_path = ../../roles` in each `ansible.cfg` is relative to the `.cfg` location; ansible resolves it back to the repo's top-level `roles/` directory.

### Neovim

Plugin manager: lazy.nvim. Leader: Space, local leader: comma.

Source of truth is Fennel under `files/nvim/fnl/` (`settings.fnl` + `mappings.fnl` + `plugins/*.fnl`); the `lua/` tree is generated by nfnl on save and is gitignored (only `lua/plugins.lua` is committed as the bootstrap). `settings.fnl` defines vim options and explicitly invokes `(mappings.general)`, `(mappings.window)`, `(mappings.lsp)` so the keymaps are actually registered. `mappings.fnl` exports functions `general`, `window`, `lsp`, `telescope`, `oil`, `autocomplete`.

LSP uses the new `vim.lsp.config`/`vim.lsp.enable` API (not the old `lspconfig.setup`). Configured LSPs: html, sqls, ts_ls, lua_ls, yamlls, bashls, jsonls, tofu_ls, ansiblels, elm_ls, pyright, **fennel_ls**. Formatting is handled by conform.nvim (stylua for Lua, **fnlfmt for Fennel**, prettier for JSON/markdown/JS/TS, ruff for Python, elm-format for Elm, LSP fallback for others). LSP provides diagnostics and code actions.

Treesitter parsers: lua, sql, css, bash, yaml, json, html, javascript, typescript, just, python, elm, **fennel**. The `html` tree is registered for `mustache`. Completion via nvim-cmp with LuaSnip and cmp-nvim-lsp. Paredit is enabled for `fennel`. Justfile support: treesitter `just` parser, the `just-lsp` server (brew formula, custom `vim.lsp.config` in `lsp-config.fnl`) and `just --fmt` as an in-place conform formatter on `just` filetypes.

#### Fennel gotchas

These cost real time during the migration, watch for them:

1. **Top-level `require` of a lazy plugin fails** with `module 'X' not found` when lazy loads the spec. The plugin is not on the runtimepath yet. Move the `require` inside the `:config` lambda, or declare the spec with `:dependencies` so lazy loads it first.
2. **`cmp_nvim_lsp.default_capabilities` is a function, not a value.** Pass the result of calling it (`(require :cmp_nvim_lsp).default_capabilities()`), not the field. Otherwise `vim.tbl_deep_extend` raises `expected table, got function`.
3. **Never drop the leading `:` on a keyword.** A keyword like `:.git/` or `:ui-select` always compiles to the string `".git/"` / `"ui-select"`, special characters included — there's no need to write it as a quoted string. The real danger is _omitting_ the colon: a bare symbol like `ui-select` (no `:`) compiles to a reference to an undefined global variable instead of a string, and silently breaks lookups.
4. **Wildcard LSP config** — `(vim.lsp.config "*" {...})` applies to every LSP. When it touches `capabilities`, wrap the value in a function so it is computed lazily (otherwise `cmp_nvim_lsp` is required at load time and may not be ready).
5. **Empty function body** — `(fn [])` does not compile. Use `(fn [] nil)`.
6. **Keymaps defined in `mappings.fnl` are not registered automatically.** `M.general` etc. are just functions; `settings.fnl` must call them. Forgetting this silently breaks `<leader>q` and friends.
7. **Compiling outside a fennel buffer** — nfnl's ftplugin only triggers on buffer open. To compile a single file from a script or `--headless`:
   ```
   nvim --headless -c "lua require('nfnl.api')['compile-file']({ path = './fnl/x.fnl' })" -c "qa!"
   ```

### Profile System

`.zprofile` sources up to three profile files in order: `~/.life_profile`, `~/.linux_profile`, `~/.private_profile`. Life and linux profiles are symlinked by Ansible; `.private_profile` is written in-place by Ansible using `lineinfile`. Profiles contain environment variables, PATH entries, and project aliases. Profiles carry only environment-specific tool setup: brew shellenv and Homebrew Paths on life; opencode bin on linux. The shared tool setup lives in `.zshrc` once for both environments: `llm` alias, `~/.local/bin` PATH, direnv hook, `EDITOR`, repo aliases (generate-aliases), and mise activation (last, so it captures the resolved PATH). `.zshrc` has no environment gating.

### Secrets

Ansible Vault encrypts `roles/life/vars/main.yml` and `roles/linux/vars/main.yml`. API tokens (GITHUB_TOKEN, ANTHROPIC_API_KEY) are written to `~/.private_profile` by the life role.

## Key Conventions

- Ansible task names use Title Case (e.g., `Install Dependencies`).
- Config deployment is always via symlinks — never copy files into `$HOME`.
- Ghostty has three configs: `built-in` (all macOS), `external` (unused), `linux`.
- Each environment's `systems/<env>/AGENTS.md` (life, linux) is symlinked into `~/.config/opencode/AGENTS.md` respectively by its corresponding role.
- The `workstation` script must be run from the repo root (`~/.dotfiles/`).
- The `justfile` is the source of truth for the workstation commands. Update the justfile and AGENTS.md together when changing it.
- Host signal `os()` resolves the `cfg`/`playbook` variables (`macos` → life tree, `linux` → linux tree) in the justfile.
- Use `prettier . --write` to format Markdown files, `just --fmt` for the justfile, `stylua .` for Lua, `ruff check --fix` for Python, and `fnlfmt` for Fennel (handled by `conform.nvim` in the editor).

## Direction

End state: Fennel for the Neovim config, justfile + sh for the CLI, Ansible for deployment. Trim playbooks and roles when they grow.
